# Dev Log 2026-11-06: Speech-Input Failure Diagnosis & Pivot

## Goal
Ship on-device speech-to-text on a real Android device (Redmi K40 / mainland MIUI) that handles **both Chinese and English** — including code-switching within a single utterance.

## Three paths tried (all failed or rejected)

### 1. WebView getUserMedia + MediaRecorder
- Symptom: tapping the mic threw `Could not start audio source`.
- Root cause: in an Android WebView, `getUserMedia` already holds the mic's `AudioRecord`. `MediaRecorder.start()` tries to open a second `AudioRecord` and always fails. MediaRecorder and getUserMedia are mutually exclusive inside a WebView — unfixable.

### 2. Web Audio ScriptProcessorNode direct capture
- Symptom: the voice card looked fine, but releasing produced no text in the box.
- Root cause: on MIUI / Redmi WebViews, `ScriptProcessorNode.onaudioprocess` frequently never fires, so `recPCM` stayed empty → silent failure.
- Also fixed a race during this: `vEnd()` (on release) called `stopRec()` before `startRec()` had actually captured anything (empty PCM). After fixing the race there was still no output, proving the capture layer itself is unreliable on MIUI WebView — not just a race.
- We also tried AudioWorklet-first / ScriptProcessor-fallback; it hit the same capture wall.

### 3. Native Vosk plugin (capacitor-offline-speech-recognition)
- Rejected because: Vosk uses **single-language models** — one model recognizes one language, and the plugin runs one language per session (`startRecognition({language})`); there is no "one model does both zh+en". True seamless code-switching needs loading zh + en models and switching by content, which the plugin does not expose — we'd have to hand-build native dual-model logic, back to the "build it ourselves" trap.
- Conclusion: Vosk can't satisfy the zh+en mixed scenario. Dropped.

## Key conclusion: the wall is capture, not the model
- `MainActivity.java` force-grants the mic and there is no CSP blocking the CDN → transformers.js successfully downloads `Xenova/whisper-tiny` and runs it in WebView WASM.
- Every failure happened at "mic audio never reaches JS"; the Whisper model was never the culprit.

## Adopted approach (this effort)
Stop capturing inside the WebView. Instead:
- **Native side**: record with `AudioRecord` (16 kHz mono) and write a WAV file.
- **Web side**: feed the WAV into transformers.js Whisper (multilingual model — naturally handles zh+en code-switching) for transcription.
- Benefits: fully bypasses the WebView capture wall, guaranteed to run on real Android, no NDK needed, builds with the existing JDK+SDK toolchain.

The voice input ships as a **standalone Whisper voice app** on the `whisper-voice-1.2` branch, with the app version bumped to 1.2 (prior versions are considered unusable because voice never worked).
